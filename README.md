- 模型：支持智谱 GLM 和兼容 OpenAI Chat Completions 的服务。通用配置为 `LLM_PROVIDER`、`LLM_API_KEY`、`LLM_MODEL`、`LLM_BASE_URL`；GLM 旧配置仍兼容。真实业务提取需同时设置 `LLM_MODE=live` 和 `ALLOW_EXTERNAL_MODEL=true`，重启后生效。这会将上传协议的文本提交给所选服务。
- 邮件：`OUTBOUND_MODE=live`，配置 `SMTP_HOST/PORT/SECURE/USER/PASS/FROM`、`MAIL_TO`。SMTP 使用 TLS 证书校验。
- 飞书：`OUTBOUND_MODE=live`，配置自定义群机器人 `FEISHU_WEBHOOK_URL`、`FEISHU_KEYWORD`，采用机器人关键字安全设置。首版只发送群提醒，签名校验机器人暂不支持。
- 自动发送还需要 `SCHEDULER_ENABLED=true`、网页对应渠道计划启用和有效目标。仅填凭据不会自动打开计划。手动模拟扫描固定使用 mock。

## 一键联合提取与补充要求

进入项目的「协议文件」，上传并打开已解析的协议，点击「一键提取事件与义务」。默认同时提取关键事件、义务及期限规则；可在「补充提取要求（可选）」输入自然语言，例如“重点提取工商登记、材料交付和季度报表，保留每条来源”。留空即使用默认要求，最多4000字；要求会随批次保存。

审核页同时展示事件候选、义务候选、原文及关联。准确建议无需逐项打开表单：核对选择结果，点击「预览确认结果」，确认日期和待补条件，勾选「已核对所选候选和原文」，再点击「确认生成正式记录」。提取、编辑候选和预览均不会新增正式事件、义务或事项。

原文明确的实际日期可自动预填；“应于某日完成”不会被当作已经发生。仅写“签署后”“交割后”的触发事件保留空日期，确认后相关事项为待事件。周期首期未说明时保留频率及偏移、提示补充首期，该条可暂不导入，其余候选可先确认。需要工作日日历时可统一选一个已确认版本；不确定的日历不自动猜测。关联其他已有事件时可明确选择；精确同源重复提取会复用原记录，不覆盖人工修改，存在日期冲突时提示核查。修改已确认事件仍走影响预览。

更改候选、选择或共同日历后需要重新预览。保存或确认失败会保留当前内容；重复确认和响应丢失重试不重复生成记录。部分片段失败时会说明当前仅有成功部分，可先审核这些候选或回到原文重新提取。原有提取批次继续使用原审核流程。

当前主应用仍为模拟模型和模拟通知、自动计划关闭。模拟模式只演示确定性提取及部分关键词筛选；复杂自然语言补充要求的效果需真实模型验证。真实提取使用已有的模型配置及外部数据开关，本轮开发不会自动启用或发送真实协议。扫描件仍需先转换为文字型文件。

本功能增加schema5事件候选表，首次启动会保留数据升级；备份中包含候选、补充要求与原件。若需回到升级前状态，使用升级前的封口备份恢复到全新目录核对，不能直接覆盖运行中的数据库。
