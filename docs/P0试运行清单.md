# P0 试运行清单

本清单对应第五项“P0补修与试运行准备”。先用合成协议完成本机演练，再由业务人员决定真实试点范围。当前主实例入口为 http://127.0.0.1:8765，模型及通知保持模拟，自动提醒关闭。

## 独立目录演练

在项目根目录执行 `npm run rehearsal:prepare`，命令会打印一个中文带空格的全新目录。该目录只复制源码、合成样例和交接说明；配置来自 `.env.example`，不复制真实 `.env`、数据库、附件、备份或发送台账。

进入打印的目录，先按README切换到Node.js 22.22.2（使用nvm时执行 `nvm use 22.22.2`），再安装依赖，避免SQLite原生依赖与启动运行时不匹配。把其中 `.env` 的 `PORT` 改为一个空闲端口，例如 `18767`，以免与主实例冲突，然后执行：

```text
npm ci
npm run doctor
npm run db:migrate
npm run build
npm start
```

打开对应的本机地址。已缓存依赖的本机可用 `npm ci --offline --no-audit --no-fund`。不要复制其他平台的依赖目录。保留 `LLM_MODE=mock`、`ALLOW_EXTERNAL_MODEL=false`、`OUTBOUND_MODE=mock` 和 `SCHEDULER_ENABLED=false`。

## 人工核对顺序

1. 新建一个明确标为“合成演练”的项目，登记合成协议实际引用的事件；未知日期保留空值。
2. 上传 `tests/fixtures/agreement.txt`，打开原文及来源位置，使用模拟提取；逐条核对义务主体、动作、期限规则、起算事件及日历，再确认导入。确认前不得出现正式义务。
3. 检查固定期限、周期各期和持续区间。人工改期先看影响预览，确认后再改事件，检查人工期限仍被保留。工作日日历必须核对来源、覆盖范围和调休。
4. 上传一份合成凭证并完成事项，检查完成日期、说明、原件下载及历史记录。重开或取消后再次核对状态。
5. 在提醒中心分别生成邮件、飞书预览，切换渠道后应重新生成；仅确认模拟发送。模拟完成不表示真实收件，已完成事项不进入自动催办。
6. 翻页检查原件、事件、义务、发送记录和扫描记录，核对总数；规则选择器应能选择首100条之外的事件及日历。失败后保留草稿，上传重试不增加重复版本。
7. 创建封口备份，执行新目录恢复，核对项目、事项、原文、凭证、审计与通知历史；恢复前不覆盖运行中的数据。

构建后可执行 `node --import tsx scripts/verify-local.ts`，自动完成合成业务闭环、重启持久化、备份及新目录恢复；使用独立临时数据库，结果写入演练目录的 `docs/Mac业务验证.json`。

## 进入真实业务试点前

业务人员需确定一份获准使用的脱敏协议、人工标准答案、可接受的提取遗漏范围，以及邮件与飞书的接收目标。协议解释有疑问的规则保持待确认；真实AI提取须明确允许把该文本提交给已配置服务。旧固定合成联调的发送授权已使用，不作为新增业务外发授权。

启用真实自动提醒还需落实常驻运行、自动重启、失败告警、日志轮换、定时备份与稳定出网。电脑关闭或休眠时不能按时发送。当前代码已在 Windows Server 2022 runner 完成原生安装器构建、静默安装和安装后 `/health` 冒烟（run 43697201602）；该证据不替代真实业务协议试点或全天候运行验收。

扫描件OCR、多人权限/复核、跨项目事项工作台、事项月历、批量操作和业务导出仍属后续开发，不计入本次P0补修完成范围。
