# 开发决定

2026-11-11：采用实施细则默认方案，本机单人、Node 22.22.2、React/TS/Vite 6、Express 5、SQLite better-sqlite3 与 Drizzle、Zod 3、npm workspaces。固定稳定版本并生成锁文件。根目录无已有工程、无 git，不创建隔离 worktree，不改需求文档和旧项目。

需求及实施细则已给出设计，用户明确要求直接编码、阶段后继续，因此沿用设计，不增加设计审批。数据库以实体逐条存储、JSON 业务载荷加数据库生成的约束列和唯一索引；所有更新版本校验、关键命令同事务审计。

外部模型和通知默认 mock；live 需要显式环境开关。凭据不进入前端或备份。日期仅 UTC 纯日期运算，业务时钟统一上海时区；工作日未确认不得成为有效期限。

数据库迁移1为实体、索引和唯一性；2增加日期有效性触发器；3增加精确AI来源指纹；4增加项目归属关系触发器。Drizzle用于实体访问，SQLite事务与版本条件更新确保权威保存。JSON载荷不等于整库JSON覆盖，日期和关键关联同时由数据库验证。

AI精确去重使用文件版本、定位/分句索引、原文和义务内容，不包含负责人或审核元数据。同版本同定位同内容可关联既有义务，保留人工编辑；不同动作、位置或文件不合并。提醒明细与不可变批次独立保存，模拟成功亦保留终态。

期限计划保守校验全部依赖版本和成员集合；预览后新增事项会要求重新预览。人工覆盖必须明确解除。修改义务普通字段只同步仍继承原值的开放事项，不改已完成快照或重置提醒时间版本。

迁移撤回采用软删除/归档，不硬删原始记录或映射；版本变化或新增后代会阻挡撤回。未知历史期限用明确未知起算事件和待审核规则表达，不造业务日期。备份封口前核对权威原件摘要，恢复只读验证备份且拒绝覆盖目标。

飞书默认关键字机器人模式，签名密钥机器人暂不支持；不把它列为已真实联调。测试使用本机已安装Edge，其他平台安装Playwright Chromium。开发代理及启动器遵循.env的PORT配置。

初始化参考核对：[Node LTS](https://nodejs.org/en/about/previous-releases)、[Vite](https://vite.dev/guide/)、[Express 5](https://expressjs.com/en/5x/api/)、[Drizzle SQLite](https://orm.drizzle.team/docs/sqlite/get-started-sqlite)、[GLM](https://docs.bigmodel.cn/cn/api/introduction)、[SMTP](https://nodemailer.com/smtp)、[飞书机器人](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)。实际依赖稳定版本以package-lock.json为准。
